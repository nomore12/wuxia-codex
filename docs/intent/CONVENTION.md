# INTENT 기록 규약

이 문서는 에이전트를 위한 지시문이다. `docs/intent/`에 결정을 기록하거나 조회할 때
이 규약을 따른다. 사람이 읽는 설명서가 아니라 실행 규칙으로 취급한다.

---

## 0. 목적과 범위

`docs/intent/`는 **diff에 남지 않는 정보**만 보관한다.

| 정보 | 보관 위치 |
|---|---|
| 무엇을 바꿨는가 | git diff |
| 어떤 순서로 바꿨는가 | git log |
| 왜 **다른 선택지를 버렸는가** | `docs/intent/` |
| 그 판단이 딛고 선 **가정** | `docs/intent/` |
| 그 가정이 깨지는 **조건** | `docs/intent/` |

커밋 메시지로 충분한 내용은 INTENT에 쓰지 않는다. 중복은 규약을 형해화시킨다.

본 CONVENTION.md는 append-only 대상이 아니다. 규약 자체는 필요할 때 직접 수정한다.
append-only는 `decision.md`에만 적용된다.

---

## 1. 작성 트리거

아래 중 **하나라도** 해당하면 작성한다.

- 되돌리는 비용이 파일 3개 이상의 연쇄 수정을 유발하는 변경
- 세계관 정전(正典) 판단 — 설정 간 충돌을 한쪽으로 정리한 경우
- 검증 파이프라인 규칙 추가/변경 (`validate.py`, `build_index.py`, `check_name.py`)
- 문서 스키마·분류 체계 변경 (4단계 분류, 세력 문서 8종 형식 등)
- 직관에 반하는 선택 — 6개월 뒤 "왜 이렇게 안 했지"가 나올 만한 것
- 사용자가 명시적으로 요청한 경우

아래는 **작성하지 않는다.**

- 리팩토링, 오타 수정, 포매팅
- 명백한 버그 수정 (대안이 존재하지 않는 경우)
- 기존 규칙을 그대로 적용한 신규 문서 추가
- 실험적 시도 — 확정되기 전까지는 기록하지 않는다

애매하면 **작성하지 않고 사용자에게 묻는다.** 과잉 기록이 미기록보다 해롭다.

---

## 2. 절대 규칙

1. **append-only.** 기존 `decision.md`를 수정하지 않는다. 판단이 바뀌면 새 파일을
   만들고 `supersedes` 필드로 이전 id를 가리킨다. 오타 수정만 예외로 허용한다.
2. **git을 건드리지 않는다.** commit --amend, rebase, 커밋 트레일러 자동 삽입 금지.
   커밋 연결은 사용자가 직접 한다.
3. **검수 없이 저장하지 않는다.** 초안을 대화에 먼저 제시하고 사용자 승인을 받은 뒤
   파일을 쓴다.
4. **사후 미화 금지.** 실제로 검토하지 않은 대안을 지어내지 않는다. 검토하지 않았으면
   「검토하지 않음」이라고 쓴다. 근거가 "그냥 그게 나아 보였다"였다면 그대로 쓴다.
5. **추측한 가정을 단정하지 않는다.** 사용자가 말하지 않은 의도를 채워 넣지 말고,
   `?` 표시와 함께 확인 요청 항목으로 남긴다.

---

## 3. 파일 구조

```
docs/intent/
├── INDEX.md                        # build_intent_index.py가 생성. 손으로 편집 금지
├── 0001-<slug>/
│   ├── decision.md                 # 필수
│   └── transcript.md               # 선택. 원본 대화 발췌
└── 0002-<slug>/
    └── decision.md
```

- id는 4자리 zero-padded 정수. 기존 최대값 + 1. 재사용·재정렬 금지.
- slug는 소문자 영문 + 하이픈, 5단어 이내. 한글 금지 (경로 안정성).
- `transcript.md`는 판단 과정이 길었을 때만 첨부한다. 전체 로그가 아니라 **발췌**다.

---

## 4. decision.md 스키마

```markdown
---
id: "0002"
date: YYYY-MM-DD
status: active            # active | superseded | retroactive
supersedes: null          # "0001" 또는 null
superseded_by: null       # 뒤집힌 뒤 이 필드만 예외적으로 갱신 허용
scope:                    # 이 결정이 지배하는 경로. glob 허용
  - scripts/validate.py
tags: [ci, tooling]       # 아래 tag 목록에서만 선택
---

# 한 문장 서술형 제목 (결정 내용 자체)

## 문제
왜 결정이 필요했는가. 관찰된 사실 위주로. 가능하면 수치.

## 검토한 대안
1. **이름** — 버린 이유. 한두 문장.
2. **이름** — 버린 이유.
3. **이름** ← 선택

## 근거
선택지가 다른 것들을 이긴 이유. 「더 낫다」가 아니라 「무엇을 기준으로 더 나은가」.

## 가정
- 이 판단이 참이라고 전제하는 것들. 검증 가능한 형태로.

## 폐기 조건
위 가정이 어떻게 깨지면 이 결정이 무효가 되는가. 그때 이동할 대안 번호.
```

**필드 제약**

- `status: retroactive` — 과거 결정을 소급 기록한 경우. 기억에 의존한 재구성이므로
  신뢰도가 낮다는 표시다. 소급 기록 시 반드시 이 값을 쓴다.
- `tags` 허용값: `canon`, `schema`, `pipeline`, `tooling`, `ci`, `naming`, `content`
  — 새 태그가 필요하면 사용자에게 먼저 확인한다.
- 전체 50줄 초과 시 결정이 두 개 이상 섞인 것이다. 분할을 제안한다.

---

## 5. 작성 절차

1. 대상 변경의 diff와 대화 맥락에서 문제·대안·근거·가정을 추출한다.
2. 추출 결과를 **초안으로 대화에 출력한다.** 파일을 만들지 않는다.
3. 불확실한 항목은 `? 확인 필요:` 접두어로 표시하고 사용자에게 질문한다.
4. 승인 후 디렉터리와 `decision.md`를 생성한다.
5. `python scripts/build_intent_index.py` 실행. INDEX.md를 손으로 쓰지 않는다.
6. 커밋은 하지 않는다. 사용자에게 넘긴다.

---

## 6. 조회 절차

사용자가 "왜 이렇게 되어 있지", "이거 바꿔도 되나"를 물으면:

1. `docs/intent/INDEX.md`에서 `scope`가 해당 경로를 포함하는 항목을 찾는다.
2. `status: superseded`면 `superseded_by`를 따라 최신 결정까지 이동한다.
3. **번복 이력 전체를 요약한다.** 최신 결정만 보고하지 않는다. 뒤집힌 횟수 자체가
   그 영역이 불안정하다는 정보다.
4. 「폐기 조건」이 이미 충족되었는지 현재 코드/문서 기준으로 검토해 보고한다.

변경 작업 착수 전, 해당 scope에 active 상태 결정이 있으면 **먼저 알리고 진행 여부를
확인한다.** 조용히 뒤집지 않는다.

---

## 7. 다중 에이전트 역할 분담

<!-- 프로젝트별 조정 구간 -->

| 에이전트 | 역할 |
|---|---|
| Claude Code (Opus) | 판단이 필요한 전부 — 추출, 초안 작성, 충돌 검토, 정전 판정 |
| Codex | 승인된 초안의 파일 생성·이동, 스키마 기계적 검증 |
| Gemini CLI | INDEX 집계, scope 교차 조회, 번복 이력 열거 |

Codex와 Gemini CLI는 `decision.md`의 **내용을 생성하거나 수정하지 않는다.**
판단은 Claude Code로 위임한다.

## 8. CLAUDE.md 삽입 블록

아래를 CLAUDE.md에 넣는다. 본 규약 전문은 필요할 때만 읽는다.

```markdown
## 의도 기록 (docs/intent/)

되돌리기 비용이 큰 결정, 정전 판단, 검증 규칙 변경은 `docs/intent/`에 기록한다.
- 규약 전문: `docs/intent/CONVENTION.md` — 작성·조회 전에 반드시 읽는다.
- append-only. 기존 decision.md 수정 금지. 번복은 새 파일 + supersedes로만.
- 검수 없이 파일을 만들지 않는다. 초안을 먼저 대화에 제시한다.
- 파일 수정 착수 전 해당 경로에 active 결정이 있는지 INDEX.md에서 확인한다.
```
